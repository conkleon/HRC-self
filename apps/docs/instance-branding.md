# Instance Branding

A self-hosted instance can replace Shelf's name, orange accent, icon and login
background with its own. The branding applies to the whole instance, not to one
workspace. It is set once by whoever runs the server, through environment
variables and a folder of images, and a restart applies it. No rebuild is needed.

Every setting is optional. An instance that sets none of them looks exactly like
Shelf.

## Settings

| Variable              | Example      | What it changes                                                                                       |
| --------------------- | ------------ | ----------------------------------------------------------------------------------------------------- |
| `APP_NAME`            | `HRC Assets` | The product name in tab titles, login and onboarding screens, the sidebar, emails and PDFs            |
| `INSTANCE_NAME`       | `HRC Patras` | The server name in the Companion app, and a line under the login logo when it differs from `APP_NAME` |
| `BRAND_PRIMARY_COLOR` | `#C8102E`    | The accent color: buttons, links, focus rings, highlights, charts, email buttons                      |
| `BRANDING_DIR`        | `/branding`  | The folder the images below are read from                                                             |
| `HELP_SITE_URL`       | `https://help.example.org` | Base of every "Learn more", knowledge-base, blog and privacy link. Unset hides them      |
| `LABEL_STORE_URL`     | `https://store.example.org` | The sidebar's "Asset labels" link. Unset hides it                                       |

The host in `SERVER_URL` is printed on QR and barcode labels ("Powered by
<host>") and shown as the prefix of the username field.

The app name and icon also name the installed app: `/manifest.webmanifest` is
built from them, so "Add to Home Screen" on a phone shows your name and icon.

## Images

Put these files in `BRANDING_DIR` (with the Docker stack in `deploy/`, that is
the `deploy/branding/` folder, which is mounted for you):

| File          | Accepted formats            | Used for                                                                        |
| ------------- | --------------------------- | ------------------------------------------------------------------------------- |
| `icon.*`      | `png`, `svg`, `webp`, `jpg` | Login and onboarding screens, sidebar, mobile header, QR pages, emails, favicon |
| `favicon.ico` | `ico`                       | Optional. The browser tab icon; without it the icon above is used               |
| `login-bg.*`  | `jpg`, `webp`, `png`        | The image on the right of the login screen                                      |

Recommendations:

- **Icon:** a square PNG of at least 512x512 pixels. Email programs often do not
  display SVG, so prefer PNG.
- **Login background:** about 1800x1200 pixels. It is cropped to fill the
  panel, so keep the important part near the center.

Files with any other name in the folder are ignored and never served.

## Choosing the accent color

White text sits on the accent color in buttons, so the color must be dark
enough to keep that text readable (WCAG AA, a contrast of at least 4.5:1). If it
is not, the server logs a warning at startup naming the color and its contrast,
and starts anyway. Lighter and darker shades for backgrounds and hover states
are generated from the one color you choose.

An invalid value (for example `red`) is ignored with a warning, and Shelf orange
is used.

## Applying changes

With the Docker stack:

```bash
cd deploy
nano .env                 # set APP_NAME, INSTANCE_NAME, BRAND_PRIMARY_COLOR
cp ~/icon.png ~/login-bg.jpg branding/
docker compose up -d shelf
```

Browsers may keep the old images for up to an hour; a hard refresh shows the
new ones immediately.

For local development, set the variables in the root `.env` and point
`BRANDING_DIR` at an absolute folder path, then restart `pnpm webapp:dev`.

## How it works

At startup the server reads the variables and lists `BRANDING_DIR` once
(`app/modules/branding/instance-branding.server.ts`). The root loader sends the
result to every page. Tailwind's `primary-*` colors read CSS variables, and the
root document injects the instance's values for them, generated by
`app/utils/brand-palette.ts`. Images are served by the public `/branding/:file`
route, which only serves the file names listed above.

## What keeps the Shelf name

Billing and upgrade screens and emails, SSO and SCIM internals, error messages,
and links to Shelf's documentation keep the name "Shelf". The "Powered by
shelf.nu" line on printed labels is a per-workspace setting (Settings, General).
